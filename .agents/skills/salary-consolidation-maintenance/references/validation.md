# 变更验证矩阵与证据要求

v2.0历史基线为34项测试，Windows全部通过；无显示Linux会跳过桌面用例。这是历史结果，后续以当前实际收集的用例数、跳过原因和测试结果为准。

## 按改动选择检查

| 修改范围 | 必要验证 |
|---|---|
| 表头/合计识别 | 括号及空白变体、精确优先、最后合计、合计后备注、无合计回退、多sheet |
| 金额/舍入 | 实发与应发、货币符号/千分位、0/负数、空值/非数字/公式缓存、累计与舍入边界 |
| 付款映射 | xls/xlsx、标题行、重复取首条、最长严格命中、归一化后备、字段0、账号文本、未匹配 |
| 目录/月度 | 标准与相似目录、直接目录、多层子目录、多个候选、排除旧成品/映射/临时文件、输入输出保护 |
| ZIP/RAR | 实际所支持后端及格式、密码、临时清理、路径/链接/展开限制、已有xlsx时不重复导入 |
| 保存/异常 | 空结果不写、错误默认阻断、显式部分输出标记、已有成品保护、占用时另存、JSON统计 |
| GUI/偏好 | 后台流程、队列更新、预览与异常、打开文件/目录、窗口尺寸、中文、密码不保存及清空 |
| 依赖/打包 | 支持Python版本、Windows完整测试、EXE启动、必要功能的打包后验证、下载包回读 |
| 文案/文档/skill | 链接、命令、版本/事实一致性及包结构；不为纯文案添加业务测试 |

新增业务测试采用最小生成工作簿或合成加密文件。错误密码测试用专用假密码。不要复制真实工资表、付款组织名单、账号或员工姓名到测试目录。

## 常用检查

仓库根目录：

```sh
python -m pytest -q
python -m compileall -q aggregate.py app.py preferences.py
git diff --check
```

只改一项规则时先运行相关用例，涉及金额、映射、保存或依赖时再执行既有完整集。测试通过后不无故反复执行。

界面测试需真实显示环境。可运行现有`test_gui_background_job_and_preview`，但仍应按界面变动实际检查布局和操作。打包自检：

```sh
python app.py --self-test /临时目录/gui-check.txt
```

Windows EXE使用同样参数。自检结果应为`ok`，同时检查退出码与超时；现有自检仅证明打包窗口初始化，并不替代所有Excel/RAR业务的EXE端到端测试。涉及打包依赖的功能变更，应额外在打包程序验证该路径。

## 输出验收

- 源文件数与成功读取文件数是否清楚；每个可汇总sheet是否恰好对应一行。
- 金额空白数、异常数和未匹配映射数分别统计，不混为一个“成功率”。
- 七列顺序、B2、第4行表头、第5行数据、单sheet和末行合计是否符合约定。
- 合计是否等于提取到的各sheet金额之和；真实样本金额是否与源合计一致。
- 缺失缓存、解密失败和无数据是否触发预期阻断；部分报告是否有标记。
- 映射命中键是否正确，0和前导零是否保留；归一化匹配是否提示复核。
- 旧成品、源表、映射是否未被意外修改；压缩包展开目录是否清理。

## 历史对照证据与限制

原引擎与v2.0使用同一份用户授权加密样本及xls映射，七列输出和合计一致。合成数据另验证2个文件生成3行、表头/金额变体、归一化映射、标题行和0/账号文本。提供的真实大RAR也已用新版解压函数及UnRAR后端展开，核对其中EXE文件大小一致。

最初实现对实际样本只做严格包含而未匹配；原版对照发现其归一化后可匹配，v2.0已补齐。后续不要沿用“该样本必然未匹配”的旧结论。与此同时，匹配成功仍需核对公司/项目对应关系。

没有整月120份原始工资表，历史开发未完成整月金额基准回归。说明书中的整月参考值不能写成已验证事实；一次UnRAR解压也不能写成所有RAR5/加密/固实包与Windows后端均通过。
